01 / ABOUT

Not just an ML model.
A working hybrid process simulator.

ML4ChemE challenges participants to combine first-principles chemical process simulation with data-driven modelling. Start with a fully rigorous DWSIM flowsheet, learn the behaviour of one unit operation from generated simulation data, and then replace that unit with an ML model while the rest of the process continues to run in DWSIM.

03 / HACKATHON WORKFLOW

Five stages. One integrated model.

Each stage produces evidence that feeds directly into the next.

STEP 01SIMULATE

Develop the DWSIM flowsheet

Create a complete process containing, at minimum, a reactor, a separation column and a heat exchanger.

  • PFR or CSTR
  • Distillation or absorption column
  • Heat exchanger
  • Appropriate thermodynamic model
STEP 02GENERATE

Generate process data

Select meaningful variables, define physically realistic ranges and generate the dataset from the rigorous simulator.

  • Input/output identification
  • Operating-range design
  • Automated DWSIM runs
  • Dataset quality checks
STEP 03SUBMIT

Submit the ML surrogate model

Develop the ML surrogate for the one unit operation you intend to replace in the final hybrid flowsheet, validate it, and submit it as a standalone model.

  • Select one eligible unit
  • Model training & tuning
  • Validate against the DWSIM unit
  • Submit model, code & results
STEP 04HYBRIDIZE

Build the hybrid flowsheet

Replace the selected rigorous DWSIM unit with your submitted ML surrogate while keeping the remaining process units in DWSIM.

  • Replace only the selected unit
  • Integrate DWSIM + ML
  • Reconnect process streams
  • Compare rigorous vs hybrid flowsheet
STEP 05PRESENT

Present & defend

Tell the engineering story: what you built, why you chose the ML unit, how well it works and where it fails.

  • Technical presentation
  • Accuracy & speed comparison
  • Engineering interpretation
  • Technical viva / live challenge

09 / FAQ

Questions,
answered.

Initial FAQ content for the event page. Final eligibility, dates and submission rules can be added before launch.

What exactly is the “hybrid model” in ML4ChemE?+

A complete DWSIM flowsheet in which one eligible rigorous unit operation is replaced by a trained ML model, while the remaining units continue to operate in DWSIM.

Which unit operations can be replaced by ML?+

Participants may replace either a PFR, CSTR, distillation column or absorption column, subject to the final challenge rules.

Can teams use ChatGPT, Claude, Copilot or similar AI tools?+

Yes, subject to the event's AI-use declaration policy. Teams must understand, reproduce and defend all submitted work.

Does the complete process need to be built in DWSIM first?+

Yes. The rigorous DWSIM flowsheet serves as the reference process model and as the source of training and validation data for the ML unit.

What will teams submit?+

The final list can include the DWSIM flowsheet, generated dataset, source code, trained ML model, validation results, technical report / README and presentation.
